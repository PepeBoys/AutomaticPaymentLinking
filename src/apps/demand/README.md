# Приложение demand - Работа с отгрузками

## Описание

Модуль `demand` реализует работу с отгрузками (shipments/demands) МойСклад. Приложение построено на базе `payable_document_base` и переиспользует функциональность через наследование. Отгрузки используются для учета фактической передачи товаров покупателям и привязки входящих платежей.

**Важно**: Это **внутренний модуль** без REST API endpoints. Используется только через `WebhookHandler` для автоматической привязки входящих платежей.

## Основные компоненты

### 1. Доменная модель
```
┌────────────────────────────────────────────────────────────────┐
│              BasePayableDocumentEntity                         │
│              (from payable_document_base)                      │
├────────────────────────────────────────────────────────────────┤
│  + id: str                                                     │
│  + account_id: str                                             │
│  + name: str                                                   │
│  + moment: datetime                                            │
│  + applicable: bool                                            │
│  + sum: float                                                  │
│  + payed_sum: float                    ← Оплачено              │
│  + shipped_sum: float | None           ← НЕ используется       │
│  + invoiced_sum: float | None          ← НЕ используется       │
│  + agent_id: str                                               │
│  + organization_id: str                                        │
│  + meta_href: str                                              │
│  + project_meta_href: str | None                               │
│  + sales_channel_meta_href: str | None                         │
├────────────────────────────────────────────────────────────────┤
│  + get_unpaid_amount() -> float                                │
│      Вычислить неоплаченную сумму (sum - payed_sum)            │
│  + is_fully_paid() -> bool                                     │
│      Проверить, полностью ли оплачен документ                  │
└────────────────────────────────────────────────────────────────┘
                        △
                        │
                        │ extends (без изменений)
                        │
┌────────────────────────────────────────────────────────────────┐
│                     DemandEntity                               │
├────────────────────────────────────────────────────────────────┤
│  (все поля наследуются от базового класса)                     │
│  (нет дополнительных полей или методов)                        │
│                                                                │
│  ПРИМЕЧАНИЕ:                                                   │
│  • shipped_sum всегда None (отгрузка уже произошла)            │
│  • invoiced_sum всегда None (отгрузка не счет)                 │
└────────────────────────────────────────────────────────────────┘
```

## Примеры использования

### Использование из WebhookHandler
```python
# Поиск отгрузок для привязки входящего платежа
demands = await demand_service.find_for_payment(
    agent_id="agent_456",
    payment_sum=25000.0,
    search_by_sum=True,
    organization_id="org_789",
    prioritize_oldest=True
)

# Привязка платежа к отгрузке
await paymentin_service.link_to_document(
    payment_id="payment_123",
    document_meta_href="entity/demand/demand_456",
    linked_sum=25000.0
)

# Обновление статуса отгрузки
await demand_service.update_state(
    document_id="demand_123",
    state_id="state_paid"
)

# Поиск отгрузки по номеру
demand = await demand_service.find_by_name_and_agent(
    name="00042",
    agent_id="agent_456",
    organization_id="org_789"
)

# Получение отгрузки по href
demand = await demand_service.get_by_href(
    "https://api.moysklad.ru/api/remap/1.2/entity/demand/demand_123"
)
```

### Работа с доменными методами
```python
# Получить отгрузку
demand = await demand_service.get_by_id("demand_123")

# Проверить статус оплаты
unpaid_amount = demand.get_unpaid_amount()  # sum - payed_sum
is_paid = demand.is_fully_paid()            # payed_sum >= sum

# Информация об отгрузке
print(f"Отгрузка {demand.name}")
print(f"Сумма: {demand.sum}")
print(f"Оплачено: {demand.payed_sum}")
print(f"Осталось оплатить: {unpaid_amount}")
```

## Интеграция с системой webhook
```
┌────────────────────────────────────────────────────────────────┐
│              РОЛЬ В АВТОМАТИЧЕСКОЙ ПРИВЯЗКЕ                    │
└────────────────────────────────────────────────────────────────┘

WebhookHandler при обработке ВХОДЯЩИХ платежей:

1. Получает платеж (paymentin/cashin) через PaymentService
2. Ищет подходящие документы (customerorder, invoiceout, demand)
3. Приоритизирует документы (заказы → счета → отгрузки)
4. Привязывает платеж к найденным документам
5. Применяет статусы (опционально)

┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  МойСклад → Webhook → WebhookService → WebhookHandler           │
│                                               │                 │
│                          ┌────────────────────┼────────────┐    │
│                          │                    │            │    │
│                          ▼                    ▼            ▼    │
│                   PaymentService    CustomerOrderService  ...   │
│                     (paymentin)            │                    │
│                          │                 │                    │
│                          │                 ▼                    │
│                          │          DemandService               │
│                          │          find_for_payment()          │
│                          │                 │                    │
│                          ▼                 ▼                    │
│                    get_by_href()    [DemandEntity]              │
│                          │                 │                    │
│                          └────────┬────────┘                    │
│                                   │                             │
│                                   ▼                             │
│                         link_to_document()                      │
│                         update_states()                         │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

## Отличия от других документов
```
╔═══════════════════════════════════════════════════════════════════╗
║         CUSTOMERORDER vs INVOICEOUT vs DEMAND                     ║
╠═══════════════════════════════════════════════════════════════════╣
║                                                                   ║
║  ┌──────────────┬────────────┬────────────┬──────────────┐        ║
║  │ Документ     │ Тип        │ Shipped    │ Invoiced     │        ║
║  ├──────────────┼────────────┼────────────┼──────────────┤        ║
║  │ customerorder│ Заказ      │ ✓ Есть     │ ✓ Есть      │        ║
║  │ invoiceout   │ Счет       │ ✓ Есть     │ ✗ Нет       │        ║
║  │ demand       │ Отгрузка   │ ✗ Нет      │ ✗ Нет       │        ║
║  └──────────────┴────────────┴────────────┴──────────────┘        ║
║                                                                   ║
║  ПРИОРИТЕТ ПРИВЯЗКИ ПЛАТЕЖЕЙ:                                     ║
║  1. customerorder  → Заказ (основной документ)                    ║
║  2. invoiceout     → Счет (выставлен счет)                        ║
║  3. demand         → Отгрузка (товар уже отгружен)                ║
║                                                                   ║
║  ОБЩИЕ ПОЛЯ:                                                      ║
║  • sum           → Общая сумма документа                          ║
║  • payed_sum     → Оплачено по документу                          ║
║  • agent_id      → Контрагент (покупатель)                        ║
║  • organization_id → Организация (продавец)                       ║
║                                                                   ║
║  МЕТОДЫ:                                                          ║
║  • get_unpaid_amount() → sum - payed_sum                          ║
║  • is_fully_paid()     → payed_sum >= sum                         ║
║                                                                   ║
╚═══════════════════════════════════════════════════════════════════╝
```

## Архитектурное решение: внутренний модуль
```
╔═══════════════════════════════════════════════════════════════════╗
║              ПОЧЕМУ НЕТ REST API ENDPOINTS?                       ║
╠═══════════════════════════════════════════════════════════════════╣
║                                                                   ║
║  ПРИЧИНЫ ДИЗАЙН-РЕШЕНИЯ:                                          ║
║                                                                   ║
║  1. Отгрузки используются ТОЛЬКО для автоматической привязки      ║
║     • WebhookHandler находит отгрузки                             ║
║     • Никакого ручного управления не требуется                    ║
║     • UI не нужен доступ к отгрузкам                              ║
║                                                                   ║
║  2. Приоритет документов (заказы важнее отгрузок)                 ║
║     • Сначала ищется customerorder                                ║
║     • Потом invoiceout                                            ║
║     • В последнюю очередь demand                                  ║
║                                                                   ║
║  3. Упрощение архитектуры                                         ║
║     • Меньше кода для поддержки                                   ║
║     • Меньше attack surface                                       ║
║     • Четкое разделение: public vs internal                       ║
║                                                                   ║
║  КОГДА МОЖЕТ ПОНАДОБИТЬСЯ API:                                    ║
║  • Если нужен UI для просмотра отгрузок                           ║
║  • Если требуется ручная привязка платежей к отгрузкам            ║
║  • Если нужна интеграция с другими системами                      ║
║                                                                   ║
║  В текущей реализации это не требуется, поэтому API нет.          ║
║                                                                   ║
╚═══════════════════════════════════════════════════════════════════╝
```
