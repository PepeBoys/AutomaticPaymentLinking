# Приложение paymentout - Исходящие платежи

## Описание

Модуль `paymentout` реализует работу с исходящими безналичными платежами поставщикам в системе МойСклад. Это **наследник** модуля `payment_base`, добавляющий минимальный специфичный функционал и REST API endpoint.

**Ключевое назначение**: Обработка webhook'ов об исходящих платежах и автоматическая привязка к документам (заказам поставщикам, счетам, приемкам).

**ВАЖНО**: Исходящий платеж = от нас поставщикам (противоположность входящему платежу от покупателей).

## Примеры использования

### Получение платежа через REST API
```python
# GET /paymentout/payment_123
response = await client.get("/paymentout/payment_123")

# Response:
{
  "id": "payment_123",
  "name": "00042",
  "sum": 50000.0,
  "agent": {"meta": {"href": ".../counterparty/supplier_456"}},  # Поставщик
  "paymentPurpose": "Оплата по счету №42 от 01.01.2024",
  "operations": [
    {
      "meta": {"href": ".../purchaseorder/order_789", "type": "purchaseorder"},
      "linkedSum": 50000.0
    }
  ]
}
```

### Обработка в webhook handler
```python
from apps.paymentout.services.paymentout_service import PaymentOutService
from apps.purchaseorder.services.purchaseorder_service import PurchaseOrderService

# Webhook payload
webhook_data = {
    "action": "CREATE",
    "events": [{
        "meta": {
            "href": "https://api.moysklad.ru/api/remap/1.2/entity/paymentout/payment_123",
            "type": "paymentout"
        }
    }]
}

# 1. Получить платеж
payment_service = PaymentOutService(auth_service)
payment = await payment_service.get_by_href(webhook_data["events"][0]["meta"]["href"])

# payment.sum = 50000.0
# payment.agent_id = "supplier_456"  ← Поставщик!
# payment.payment_purpose = "Оплата по счету №42"

# 2. Найти документы для привязки (ЗАКАЗЫ ПОСТАВЩИКАМ, не покупателям!)
order_service = PurchaseOrderService(auth_service)
orders = await order_service.find_for_payment(
    agent_id=payment.agent_id,  # supplier_456
    payment_sum=payment.sum
)

# 3. Привязать платеж к найденным документам
for order in orders:
    payment = await payment_service.link_to_document(
        payment_id=payment.id,
        document_meta_href=order.meta_href,
        linked_sum=order.get_unpaid_amount()
    )
```

## Архитектурное решение: идентичность с paymentin
```
╔═══════════════════════════════════════════════════════════════════╗
║          ПОЧЕМУ PAYMENTOUT ИДЕНТИЧЕН PAYMENTIN?                   ║
╠═══════════════════════════════════════════════════════════════════╣
║                                                                   ║
║  РАЗЛИЧИЕ ТОЛЬКО В НАПРАВЛЕНИИ:                                   ║
║  • paymentin: ОТ покупателя К нам (доход)                         ║
║  • paymentout: ОТ нас К поставщику (расход)                       ║

║  1. Получить платеж из webhook                                    ║

║  3. Привязать через link_to_document                              ║
║  4. Обновить статус/проект/канал                                  ║
║                                                                   ║
║  ПОЧЕМУ НЕ ОБЪЕДИНИТЬ В ОДИН МОДУЛЬ?                              ║
║                                                                   ║
║  Аргументы ЗА объединение:                                        ║
║  • Абсолютно идентичный код                                       ║

║  • Проще поддержка                                                ║
║                                                                   ║
║  Аргументы ПРОТИВ:                                                ║
║  • Разная семантика (доход vs расход)                             ║
║  • Разные документы для привязки                                  ║
║  • Явное разделение в МойСклад API                                ║
║  • Проще понимать (входящие отдельно, исходящие отдельно)         ║
║                                                                   ║
║  ВЕРДИКТ: Правильное разделение                                   ║
║  • Type safety: PaymentOutEntity != PaymentInEntity               ║
║  • Domain clarity: явная семантика направления                    ║
║  • API clarity: /paymentin vs /paymentout                         ║
║                                                                   ║
```
