# Приложение supply - Приемка товаров

## Описание

Модуль `supply` реализует работу с приемками (поступлениями) товаров от поставщиков в системе МойСклад. Это **наследник** модуля `payable_document_base`, добавляющий минимальный специфичный функционал для регистрации получения товаров.

**Ключевое назначение**: Документирование факта получения товаров от поставщика. Supply связывает заказ поставщику (purchaseorder) с фактической приемкой товаров на склад.

**ВАЖНО**: Supply (приемка) = получение товаров ОТ поставщика НА наш склад. Это завершающий этап цикла закупки.

## Примеры использования

### Внутреннее использование в системе
```python
from apps.supply.services.supply_service import SupplyService

service = SupplyService(auth_service)

# Получить приемку по ID
supply = await service.get_by_id("supply_123")

# supply.sum = 100000.0
# supply.payed_sum = 100000.0
# supply.agent_id = "supplier_456"  # От кого получили

# Проверка оплаты
if supply.is_fully_paid():
    print("Приемка полностью оплачена")
else:
    unpaid = supply.get_unpaid_amount()
    print(f"Осталось оплатить: {unpaid}")

# Эти методы вернут None (нет данных полей)
assert supply.get_unshipped_amount() is None
assert supply.get_uninvoiced_amount() is None
```

### Поиск приемок для платежа
```python
# Найти приемки для привязки к платежу
supplies = await service.find_for_payment(
    agent_id="supplier_456",
    payment_sum=50000.0,
    search_by_sum=True
)

for supply in supplies:
    if not supply.is_fully_paid():
        print(f"Supply {supply.name}: {supply.get_unpaid_amount()} руб")
```

## Архитектурное решение

Supply является примером **правильного минимализма**:
- Нет неиспользуемого кода (value_objects)
- Нет ненужных API endpoints
- Только необходимые поля (payed_sum, без shipped_sum/invoiced_sum)
- Высочайший коэффициент переиспользования (92%)

Это показывает зрелость архитектуры - модуль добавляет ровно столько кода, сколько необходимо для своей функции.
